# Gigo · Подработка на карте

Telegram Mini App: биржа подработки в Москве. Заказчики создают заявки, исполнители находят их в ленте и на карте и откликаются.

- **Заказчик** создаёт заявку (что сделать, сколько людей, оплата, метро или адрес, когда), получает отклики в бота, принимает или отклоняет.
- **Исполнитель** смотрит ленту и карту с фильтрами (категория, ₽/час, метро, рядом, сегодня), откликается с сообщением, подписывается на новые заявки.
- После принятия обе стороны видят контакты друг друга в Telegram и договариваются напрямую. Потом оставляют друг другу отзывы, из них складывается рейтинг.
- Роль выбирается при первом входе и меняется в профиле. Оплаты внутри приложения нет: стороны рассчитываются напрямую.

```
Mini App (React) ──→ API (FastAPI) ──→ PostgreSQL + PostGIS
                                         │ outbox, подписки
                                         ↓
                                  бот (aiogram) ──→ сообщения в Telegram
```

| Часть | Где | Запуск |
|---|---|---|
| API | `backend/gigo/api` | `uvicorn gigo.api.app:app` |
| Бот | `backend/gigo/bot` | `python -m gigo.bot` |
| Mini App (React + Vite + Яндекс Карты) | `frontend` | `npm run dev` |
| База (PostgreSQL 16 + PostGIS) | `backend/gigo/migrations` | `docker compose up -d db` |

Контракт API: [docs/api.md](docs/api.md). Как выложить на сервер: [docs/deploy.md](docs/deploy.md).
Прежняя версия (сборщик объявлений из чатов) сохранена в ветке `v0-aggregator`.

## Что нужно подготовить

1. **Бот** от @BotFather: токен.
2. **Ключи Яндекс Карт** на developer.tech.yandex.ru: JavaScript API (для карты) и HTTP Геокодер (адрес заявки → точка). Без геокодера точка ставится по метро.
3. Для запуска в Telegram: **сервер и домен** (см. docs/deploy.md).

Всё вписывается в `.env` (образец в `.env.example`). Ключи не пересылаем в чат.

## Запуск на своей машине

Нужны Docker Desktop, Python 3.12 и Node 22.

```bash
cp .env.example .env              # можно пока не заполнять
docker compose up -d db           # база

cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m gigo.migrate            # таблицы
python -m gigo.metro              # станции метро Москвы с координатами (hh.ru)
python -m gigo.demo               # 3 демо-заказчика, 8 заявок, отзывы (убрать: --clear)

DEV_AUTH=1 uvicorn gigo.api.app:app --reload --port 8000

cd ../frontend && npm install && npm run dev            # http://localhost:5173
```

`DEV_AUTH=1` пускает в API без подписи Telegram, только для разработки. В браузере вы пользователь с id 1;
чтобы посмотреть вторую сторону, откройте вторую вкладку с `?devUser=2`: так проверяется весь путь
«заказчик создал заявку → исполнитель откликнулся → заказчик принял → оба видят контакты и оставляют отзывы».

Интерфейс без бэкенда, на тестовых данных: `npm run dev:mock`.

Бот (нужен `BOT_TOKEN`): `python -m gigo.bot`.

## Альфа-версия в Telegram бесплатно

Без сервера и домена: приложение работает с вашего компьютера, а HTTPS-адрес даёт бесплатный туннель:
Cloudflare Tunnel, а если он не пробивается (бывает в РФ и за VPN), localhost.run через обычный ssh.

```bash
brew install cloudflared   # один раз, желательно; без него сразу используется localhost.run
./scripts/alpha.sh
```

Скрипт поднимает базу, собирает Mini App, запускает API (вход только через Telegram) и бота, открывает туннель
и ставит его адрес в кнопку меню бота. Откройте бота в Telegram и нажмите «Gigo». Пока скрипт работает, компьютер
не засыпает. Ограничения: адрес меняется при каждом запуске (старые кнопки в чате перестают открываться), и
приложение доступно, только пока компьютер включён. Когда это начнёт мешать, переезжаем на сервер (docs/deploy.md).

Чтобы в боте появились аватар и описание: в @BotFather `/setuserpic` (картинка `docs/brand/bot-avatar-512.png`),
`/setdescription` и `/setabouttext`.

## Как это работает

**Заявка.** Оплата приводится к ₽/час (смена без длительности считается за 8 часов и помечается «≈»). Точка на карте:
координаты, переданные Mini App, иначе адрес через геокодер, иначе станция метро. Заявка уходит из ленты через час
после начала, в конце дня, если указан только день, или через 3 дня без даты. Тексты с признаками
мошенничества и вербовки (закладки, оформление карт, предоплата за обучение и т.п.) не публикуются (`gigo/rules.py`).

**Отклик.** Исполнитель откликается один раз (после отзыва можно снова). Заказчик принимает или отклоняет;
закрытие набора отклоняет всех, кто ждал. Контакт второй стороны (ссылка на профиль в Telegram) открывается только
у принятого отклика.

**Бот.** API кладёт события в таблицу `outbox` в той же транзакции, что и само действие; бот раз в 3 секунды
отправляет их: новый отклик, вас выбрали (с контактом заказчика), отказ, отмена заявки. Раз в 15 секунд бот сверяет
новые заявки с подписками исполнителей и присылает каждую подходящую один раз.

**Отзывы.** Оставляются только между заказчиком и принятым исполнителем одной заявки, повторный заменяет прежний.

**Бот.**
- Команды: /new, /my (мои заявки), /responses (мои отклики), /subs, /stop, /help.
- Новый отклик приходит заказчику с кнопками «Принять» и «Отклонить»: решить можно, не открывая приложение.
- За 2 часа до начала бот напоминает принятому исполнителю о работе. После окончания он просит обе стороны оставить отзыв.

**Модерация.**
- Жалобы на заявки приходят модераторам (`ADMIN_IDS` в `.env`) с кнопками «Скрыть», «Всё в порядке» и «Заблокировать автора».
- После 3 жалоб от разных людей заявка скрывается сама, до решения модератора.
- Команды модератора: `/ban <id> [причина]`, `/unban <id>`, `/stats`.

## Безопасность

- **Вход.** Вход в API только с подписанными данными Telegram (`initData`), подпись проверяется токеном бота, данные старше суток не принимаются. `DEV_AUTH=1` работает только для запросов с этой же машины: через туннель или прокси так не войти. Документация API (`/api/docs`) открыта только в режиме разработки.
- **Лимиты.** На заявки, отклики и жалобы есть лимиты (`429`), плюс общий лимит 60 изменений в минуту на человека.
- **Доступ.** Заблокированный пользователь получает `403` везде. Его открытые заявки скрываются, а ожидающие отклики снимаются.
- **Данные.**
  - Тексты очищаются от управляющих символов и подмены направления текста.
  - В сообщениях бота всё экранируется.
  - Контакт второй стороны виден только после принятия отклика.
  - Телефоны не собираем.
- **Мошенничество.** Тексты заявок проверяются на признаки мошенничества и вербовки (`gigo/rules.py`). Исполнителям в приложении и в боте показываются советы по безопасности.
- **Сервер.**
  - Caddy ставит HSTS и защитные заголовки и ограничивает размер запроса.
  - API в контейнере работает не от root.
  - База слушает только 127.0.0.1.
  - Ключи не пишутся в логи.
  - `.env` в `.gitignore`.
